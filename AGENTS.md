# CloudRaker Run skills

This repo ships agent skills for `rakerun`, the CLI of cloudraker.run, in the agentskills.io format. It holds two packs. Each pack is a plugin for Claude Code and Codex:

- The developer pack (plugin `rakerun`): `skills/<name>/SKILL.md`. Start with `skills/rakerun/SKILL.md`, the umbrella. It teaches git, `agent.yml`, YAML and the CLI.
- The business pack (plugin `rakerun-business`): `business/skills/<name>/SKILL.md`. Start with `business/skills/rakerun-business/SKILL.md`. The agent does every step for a person who does not use git.

If you work in this repo: the skills are hand-written docs, not generated. Keep the frontmatter to the spec keys (`name`, `description`, `allowed-tools`). Each plugin has a `.claude-plugin/plugin.json` (a list of skill folders) and a `.codex-plugin/plugin.json` (the `./skills` folder), with the same name and version. Both marketplace files (`.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json`) list both plugins. When you add a skill, add it to the Claude `plugin.json` of its pack and to the catalog of `README.md`.

Keep the house rules the same in every skill of the developer pack: a folder with `AGENTS.md` is an agent, `rakerun deploy` (or `rakerun push <env>` for an environment) is the only way to ship, `rakerun lint` before every deploy, secrets are `${secret:NAME}` references and never values. Verify every command against `rakerun --help` before you document it. Verify every `agent.yml` key against https://cloudraker-run.docs.buildwithfern.com/guides/agent-yml. Verify every `doors/{name}.yml` key against https://cloudraker-run.docs.buildwithfern.com/guides/doors-yml. Channels (web chat, phone, email, Slack, Teams) live in front doors, never in `agent.yml`.

No git words in business copy. A business skill can give the agent a command, but every sentence that the agent says to the person uses the words of the console: project, change, Draft, try it, Make it live, record type, "Linked to", team. The agent never says branch, commit, push, repo, YAML, deploy, space, reach, stamp or hop to the person. A business change is always a Draft (`changes/<slug>`): the person tries it in the console, and a publisher makes it live. The first save of a project goes live at once, so the only save on `main` is the starter of a new project. Only an admin can sign in the CLI (the `/cli` token needs the admin role), so never tell a builder that "Can build" lets the agent sign in. Read the access sentences of `rakerun lint --explain` to the person before the agent saves a change to record types or access.
